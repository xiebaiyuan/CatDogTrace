# Changelog

Notable changes to `dsh-catdogtrace`. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the package follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.0] — 2026-10-29

First release. A DeepSeek Harness client overlay for the DogCatTrace attribution: draw the
challenges, paste the model's numbers back, read the 24-breed ranking. The math is the one the Flask
page and the offline standalone file already run — same bank, same features, same calibration, no
change to the judgment.

### Added

- The `/catdog` trigger in the DSH input box, and the overlay it opens. `Esc`, the `×` button, and a
  click on the backdrop each close it.
- Three ways to feed the dialog:
  - **Draw first** — click 「生成 3 道挑战」, send each prompt to the model under test, paste each
    full reply into the box at the same index. Each box carries its own challenge's
    `expected_count`.
  - **Bare text** — paste into the boxes without drawing challenges. Flat threshold of 80 parsed
    integers; the dialog states this rather than applying it silently.
  - **JSON** — paste `{"outputs":[{"text":"...","expected_count":218}]}` into the collapsed JSON
    section. Same body `POST /api/analyze` takes in the Flask version. It wins over the three boxes
    whenever it is non-empty; an entry without `expected_count` falls back to 80.
- Result panel: both family shares, the champion breed with its global share, the descending ranking
  of all 24 breeds (global share and within-family conditional share), and every input the core
  rejected together with the count it actually parsed.
- Admission threshold `max(80, ceil(expected_count * 0.55))`, matching `fingerprint.py:241`.

### Packaging

- Two halves: `lib/index.js` is the host side (a Cordis plugin with an empty body), `lib/client.js`
  the browser side. `package.json` declares `dsh.client.platform: web`, and `cordis.patch.yml`
  supplies the loader row both halves hang off.
- `lib/client.unified_bank.js` (963,838 bytes) is the fingerprint bank as its own chunk, reached only
  through `loadBankChunk()`'s dynamic `import()` on the first overlay open. It never enters
  `lib/client.js`.
- The chunk load goes through the host's real `require.async("./client.unified_bank.js")` protocol,
  because the host's module table is frozen and a synchronous `require` fallback would miss it. The
  build rewrites the call and asserts the output in `generateBundle`; do not "fix" it back to a
  plain dynamic import.
- React comes from the host's frozen module table (a peer dependency, never bundled). No CSS
  framework: the overlay is one hand-written stylesheet injected as a single `<style>` tag and
  coloured with the host's `--dsw-*` tokens, so it follows the page theme.

### Verified

- Parity against `fingerprint.py::analyze_global_outputs` over 10 frozen cases
  (`tests/core/fixtures/python-parity.json`, generated by `scripts/gen-parity.py`, tolerance 1e-12).
  Worst deviation on per-breed probability **2.998e-15**; string and integer fields compared
  strictly.
- `tsc --noEmit` exits 0, `vitest run` is green.

### Requirements

- `dsh >= 0.2.1-rc.2` on a host that serves client bundles (`platform: web`). Restart `dsh` after
  installing — the host composes its browser module graph at boot.
- Node `^22.19.0 || >=24.0.0` for the package's own build.

### Known limits

- The plugin does not call a model. The DSH browser side can list models but cannot run a one-shot
  completion, so the user moves the prompts and the replies by hand. This is a product decision, not
  a temporary gap: it keeps the plugin independent of the host's model interface.
- Closed-set probabilities over the current bank of 24 breeds. An input that resembles nothing in the
  bank still gets an answer.
