# 0001 合成品种语料

## 状态

已接受，2026-10-17。

## 背景

参考实现的参考语料是从真实模型 API 采集的：一部分采集自厂商官方订阅通道，另一部分采集自第三方渠道。它的指纹库因此带着真实模型的行为特征。

DogCatTrace 要复刻同一套数学，但候选换成了狗猫品种。品种不是模型，没有 API，没有权重，没有可供采集的真实输出。

摆在面前的选择只有两类：要么找一批真实数字生成器（不同模型、不同温度、不同提示词），把它们的输出当作"品种"；要么直接定义一套品种参数，用参数合成输出。

## 选项

选项 A：调真实模型采集语料，把每个模型当成一个品种。

优点是与参考项目的数据形态完全一致，指纹库带着真实噪声。缺点有三条。一是引入了网络依赖，报告不可离线复现。二是引入了不确定性，同一个模型在不同时间采出来的语料不同，报告的每个百分号会随采集时间漂移，这与"每个百分号来自一次真实运行"的可复现要求冲突。三是会把真实模型的名字与"品种"这个虚构分类绑在一起，混淆演示对象。

选项 B：定义一个品种生成模型，用参数合成输出。

优点是全离线、完全确定性（同一个 seed 永远得到同一份语料），报告可逐字节复现。缺点是语料是合成的，品种之间的差异由参数保证，不含真实模型的高阶噪声。

选项 C：混合，用真实模型的输出做基准，再用参数扰动造出"品种成员"。

优点是有真实噪声底色。缺点是复杂：需要先采一批真实语料再拟合参数，而且一旦真实语料被替换，下游所有数字都要重算。复现成本最高。

## 决定

选 B。

每个品种一条 355 维权重向量，权重由四个可解释的成分相乘得到：高斯峰、值域提升、末位数字偏置、位置漂移。抽样时对每个位置按权重归一化后做 categorical 抽样。成员之间的差异用 sin 相位的确定性扰动实现，扰动幅度按成员 id 稳定确定，不引入随机。

族基准参数写在 SPEC §5.3，成员扰动幅度写在 SPEC §5.3 末尾。

## 后果

好的方面：

- 语料生成不需要网络，enrollment.py 里没有任何 HTTP 调用。
- 整个流水是确定性的。给定 seed，report.py 每次产出的数字完全一致，报告里的百分号可以逐次核对。
- 品种之间的可分性由参数控制，不会出现"某个品种碰巧跟另一个品种撞了"的情况，也不需要为演示效果调参。
- 演示对象与真实模型解耦。库里只有狗猫品种名，没有真实模型的名字，因此不存在把虚构结论套到真实模型上的风险。

代价：

- 语料是合成的，不能用来论证任何关于真实模型的结论。这一点在 README 与归因报告的"边界"一节都写明。
- 指纹库的难度低于真实语料。合成语料的品种间差异比真实模型之间的差异大，因此 cv_accuracy 会很高。这个高本身是参数设计的产物，不是方法优越性的证据。
- 如果将来要换成真实语料，enrollment.py 的接口不需要改（make_row 的字段名与参考实现一致），但 SPEC §5 的整张参数表作废，所有库要重建。
