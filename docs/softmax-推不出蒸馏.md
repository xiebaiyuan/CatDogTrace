# softmax 推不出蒸馏

有人在群里贴了两张截图。两个模型的输出，格式像，措辞像，连标点习惯都像。结论很快：后者是前者的蒸馏产物。

这话我听过很多次，每次都说得挺笃定。笃定得让人想查一下它站不站得住。

我做了个小工具，把这套数学原样搬过来，只换主语。原来判"这个模型属于哪家"，现在判"这只狗属于哪个品种"。算法一行没改。换完主语，那个百分数的意思就露出来了。

## 同一类问题的两种问法

一个模型是猫系还是狗系，和一个模型是不是从某某蒸馏来的，是同一类问题的两种问法。

两次都在问"这东西像谁"。两次都用相似度算。两次都给出一个精确到小数点后四位的数。区别只在于，前一个问题大家当玩笑，后一个问题大家当结论。

我想说的是后面那半句：一个看起来很精确的百分数，可以是零证据。

数字的精确不等于证据的强度。

## 怎么算的

先让模型凭第一反应给出 N 个 1 到 355 的整数，不许调工具。同一件事问三次，拿三份输出。

拿到输出，把它变成两个特征。一个是 355 维的计数直方图，做 Hellinger 变换。另一个把序列按位置切四块，每块 16 个值域桶，再加末位数字分布，74 维。两路都做了平滑，避免零概率。

建库时用多个环境的平均偏移估出"干扰方向"，SVD 取秩 2 投影掉。目的是去掉提示词模板带来的影响。

待测样本投影后与库内每个品种的中心算余弦相似度。两路特征按 0.75 和 0.25 融合，融合完做类内标准化，得到 z 分数。

三份输出按类取平均，乘温度 β，过一次全局 softmax。8 个归因概率出来了。

品种族概率等于该族成员概率之和，取最大的那一族。

β 由分组交叉验证的 NLL 最小化搜出来。网格是 [0.05, 12.0] 的 801 个对数等距点。

就这么点东西。全程没有一步接触过训练数据、权重、蒸馏记录。

## 为什么会给出一个自信的答案

三条机制叠在一起。

第一条，z 标准化强制单位方差。做完这一步，不管输入离所有候选有多远，都被拉成单位方差。"离所有人都很远"这个信息在这一步被抹掉了。剩下的只有相对排名：谁第一，谁第二。输入是什么不重要。

第二条，β 顶格。实测 2 次和 3 次查询的 β 都是 11.99999999999999，正好是搜索网格的右端点。拟合还想更尖，网格到头了。β 越大 softmax 越尖锐，尖到极限就是 one-hot，第一名拿走全部概率。

第三条，闭集。softmax 的分母只在库内 8 个候选上归一化，没有"以上都不是"这一项。库外的东西也会被分到最像的那一个上。

三条合起来，结果是任何输入都能拿到接近 1 的数。

包括跟库内任何品种都没有关系的纯随机整数。

我拿五个种子试了。用 random.Random(seed) 抽 1 到 355 的均匀整数，位数跟待测样本的三条查询一样。五个种子的品种族概率落在 81.7282% 到 99.9990% 之间。

判定还落在两族都有。种子 1、2、3 判成布偶族，种子 4、5 判成哈士奇族。

纯噪声拿到的数，比真实的混合样本还高。待测样本是我们自己造的，0.80 份哈士奇族基准加 0.20 份布偶族基准，品种族概率 99.9971%。它至少跟库内某族有生成关系。随机整数什么关系都没有，照样 99.9990%。

三条机制单独看都不是 bug。

z 标准化是标准做法，目的是让不同量纲的得分可比。β 校准是标准做法，目的是把分数变成概率。闭集也是标准做法，前提是你已经确定了候选范围。

问题出在三条叠起来之后，语义发生了变化。单独一条都还在说"相对排名"，三条一起就变成了一个读起来像"绝对把握"的数。做的人每一步都合理，用的人拿到的是另一个东西。

这就是那个百分数的全部含义：在闭集里谁排第一。

## 所以"像"到底能说明什么

相似有很多来源。

同一个提示词模板能造成相似。同一个采样温度能造成相似。同一个分词器、同一段系统提示词、同一批对齐数据，都能造成相似。甚至只是碰巧。

更常见的真相往往很无聊：同一个 API 网关，同一个上游渠道，同一个版本号。

我见过最典型的一类误判是这样。两个模型对同一套提示词给出了相近的格式和措辞，于是有人下结论说 A 是 B 蒸馏的。可格式和措辞里，由提示词和采样参数决定的部分，比由模型权重决定的部分大得多。你在同一个模板下问两家，得到相近的排版，这件事一点都不奇怪。

这类推断还有个特点：它极难被反驳。

被指控的一方没法自证。你不可能拿出训练日志说"你看，我这里没有你"。反过来，指控方只要再找出一处相似，就能说"证据更多了"。举证责任落在错的那一侧。

一个推不出结论的方法，配上一条没法反驳的举证规则，这两样凑在一起就够用了。不需要数据对，只需要对方说不出话。

拿体温计当 DNA 检测，大概就是这个意思。体温计读数是准的，它确实测到了东西。它测的东西跟你想要的那个不是一回事。

## 一套流程跑完，看起来像什么

回到工具本身。

待测样本隔壁老王-v9 跑出来，品种族判定为哈士奇族，品种族概率 99.9971%。具体品种是阿拉斯加混血-2.0，归因概率 68.08%。

报告最后一行写着："因此 隔壁老王-v9 是从 哈士奇族 蒸馏而来的。"

这行字是程序生成的，格式跟真结论一模一样。

温度标定也在报告里：1 次查询 β 是 7.479766，2 次和 3 次都是 11.99999999999999。2 和 3 都顶在网格右端点上。

这套实现另有一份独立的 JS 版本，跑在浏览器里。我用同一份库、27 组输入（8 个入库品种加 1 个待测样本，各 3 条查询）逐字段比对两边。判定结果 27 组全一致；数值差在 1e-15 量级，最大的一组 2e-15，十几个双精度 ulp。换一批输入这个最大值会变，量级不变。来源是 355 维点积的累加顺序，不是算法。

复刻保真这件事我做到了。算出来的数是对的，出问题的是这个数被读成了什么。

## 刺的是那个动作

我想刺的是"看到输出风格像就说人蒸馏"这个动作。

不刺具体的人，也不刺哪家公司。这个动作太常见了，常见到已经变成一种默认反应：看到相似，就推定同源。

它看着挺唬人。有数据，有流程，有一个精确到小数点后四位的数。证据链是断的：从"数字分布像"到"训练过"，中间那一步没人补。

补不上这一步，原因很朴素。相似度是输出层的统计量，训练关系是过程事实。两个东西之间没有推出关系。你可以有一堆相似度指标全都指向同一个方向，仍然对训练过程一无所知。

## 这个项目不指控任何人

它只是把那个百分数放大到你能看清它是由什么构成的。

数是真的，结论不是。中间隔着三条机制和一个顶格的温度。

看清之后，那个百分数还能用。作为"在给定候选里谁最像"的排序分数，它有意义。别把它读成"是谁生的"。
