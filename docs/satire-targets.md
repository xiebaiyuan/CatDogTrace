# 靶子逐条拆解

本文件和 README 末节「现实检查」是本仓库唯一允许明着拆靶子的两处。其余文件一律冷面学术体。

下面每条证据都给出本仓库的文件与行号。因为本项目按参考实现逐行复刻，同一处代码在两边的形态一致，所以行号只指向本仓库。

## T1 概率的输入是数字分布的相似度

证据：fingerprint.py:269

    268|     beta = float(bank["calibration"][calibration_key]["beta"])
    269|     probabilities = softmax([beta * value for value in combined_scores])

combined_scores 来自 fingerprint.py:259-266，是 valid 里每条记录的 scores[index] 取平均。scores 来自 robust_score_numbers，即两路特征（边际 Hellinger 计数特征、有序块特征）投影掉干扰方向后与库内品种中心做的余弦相似度。

也就是说 softmax 的输入是一条由随机数字算出来的相似度，输出被命名为 probability，并被下游读作"这个样本属于这个品种的概率"。

推理断在哪：

"这个样本生成的数字分布与候选 A 的库内分布相似"和"这个样本由候选 A 产生"之间，缺一条推理。相似度可以由很多原因造成，包括同一个提示词模板、同一个温度参数、同一个分词器、同一个随机源，也包括两个独立来源碰巧都偏向某几个数字。相似度不含来源信息，因此它推不出来源。

中间没有任何一步接触训练谱系。没有训练数据，没有权重，没有蒸馏记录，没有对照实验。

## T2 品种族概率是成员概率之和

证据：fingerprint.py:198-205

    198|     family_probabilities = {
    199|         family_id: sum(
    200|             item["probability"]
    201|             for item in result["results"]
    202|             if (model_entries[item["model"]].get("family") or "models") == family_id
    203|         )
    204|         for family_id in family_order
    205|     }

fingerprint.py:214 接着把这个求和结果当成"哪个品种族赢了"的判据：

    214|     winning_family = max(family_order, key=family_probabilities.get)

README.zh-CN.md:109 把这件事写成公式：

    109| P(品种族)   = Σ P(该族中的具体品种)

推理断在哪：

求和是加总，不是识别。一族有 12 个成员，另一族也有 12 个，份额大小反映的是成员概率的集中程度。成员数不等的库里，成员多的那一族天然更容易赢，因为它的概率被分成更多份再全部加回来。这个数度量的是"这一族成员合起来占了多少份额"，不是"这一族是不是源头"。

更要紧的是，求和把两种完全不同的情形压成同一个数：某族里有一个成员特别像（概率集中），和某族里每个成员都稍微像一点（概率摊平），在这一个数上看不出区别。

推理断在哪：从"一族成员概率之和最大"到"这一族是待测样本的祖先"，中间缺一步。份额大小与祖先关系没有逻辑通道。

## T3 温度 β 的搜索上界是 12.0，多数查询打在上界

证据：bank_builder.py:239

    238|     for step in range(801):
    239|         beta = math.exp(math.log(0.05) + step * (math.log(12.0) - math.log(0.05)) / 800)

搜索区间是 [0.05, 12.0]，801 个格点，按对数等距。选 β 的标准是 NLL 最小（bank_builder.py:247）。

本仓库 data/unified_bank.json 的实际校准结果：

| 查询数 | β | cv_accuracy | cv_correct / cv_samples |
|---|---|---|---|
| 1 | 8.010150 | 0.809028 | 233 / 288 |
| 2 | 11.99999999999999 | 0.949074 | 273 / 288 |
| 3 | 11.99999999999999 | 0.982639 | 283 / 288 |

2 和 3 两次查询的 β 都打在上界 11.99999999999999，等于搜索区间的右端点。1 次查询的 β 是 8.010150，落在区间内部。

推理断在哪：

β 打在上界，说明最优值不在区间内，而在区间右侧某处。搜索被截断了，报出来的 β 是"我们在区间里能找到的最好的"，不是"最优的"。这一点本身只是数值问题。

真正的问题在下一步：β 越大，softmax 输出越尖锐。β 趋近无穷时，softmax 退化成 one-hot，最大得分的那个候选拿走全部概率。当交叉验证正确率已经接近上限时，NLL 仍会因为 β 继续增大而下降，所以拟合过程会一路把 β 推到边界。于是"概率"这个数的绝对大小，实际上由搜索区间的右端点决定，不由数据决定。

把这样得到的 63.72% 读成"63.72% 的把握"，是把一个被区间上界截断的缩放因子读成了置信度。

## T4 闭集与均匀先验

证据：README.zh-CN.md:125

    125| 结果是当前候选库内、均匀先验下的闭集概率。未收录的样本仍会被归到最相似的现有候选。

证据：data/unified_bank.json 的 models 字段有 24 项，分属 dog 与 cat 两族；calibration 里三次查询的 cv_accuracy 分别是 0.809028、0.949074、0.982639。

推理断在哪：

闭集意味着候选集是有限的、事先固定的。softmax 的分母只在这 24 个候选上归一化，所以不管输入是什么，24 个概率加起来一定是 1。一个完全不在库里的样本，也会被分到最相似的那一个上，拿到一个看起来很像概率的数。分母里没有"以上都不是"这一项。

均匀先验意味着每个候选事先被当成一样可能。24 个候选各 1/24，这就是全部的先验信息。真实场景里不同品种的流行度、不同族的成员数、不同版本的迭代关系都会让先验不均等，但工具里这些信息一律不参与。

cv_accuracy 到 1.0 要单独说一句：这个数是在库内做的分组交叉验证，测的是"能不能把库里的样本认回它自己"。库内样本当然像自己。这个数高，恰恰说明它测的是闭集内的自我识别，与"能不能认出库外样本"是两回事。

推理断在哪：从"在这 24 个候选里 A 最像"到"这个样本就是 A"，中间缺一条。闭集假设把这个缺口藏起来了：因为分母一定是 24，所以任何输入都会得到一个看起来很确定的答案。

## 四条靶子的共同结构

四条靶子是同一个动作的四次重演：

1. 算一个相似度或求和（T1、T2）。
2. 用一个被区间截断的缩放因子把它放大到接近 1（T3）。
3. 在一个封闭候选集上归一化，让分母一定是有限的（T4）。
4. 把得到的小数命名为概率，再把这个概率读成因果断言。

每一步单独看都站得住：余弦相似度是合法的相似度，求和是合法的聚合，softmax 是合法的归一化，闭集是合法的假设。断的地方在最后一步：从"相似"到"同源"，没有任何一步被补上。

本项目的每一处代码都逐行复刻了这四步，一个字不为笑话改。把主语从"AI 模型"换成狗猫品种之后，同一个推理链条的缺口就露出来了：没有人会相信"因为 Clapt 的数字分布像哈士奇，所以它是从哈士奇蒸馏来的"。缺口一直都在，只是换成品种名之后不再被技术名词挡住。
